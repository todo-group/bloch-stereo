# Meta Quest 3S 実機受け入れ試験手順

この文書は、Bloch StereoのMeta Quest 3S対応を実機で最終判定するための手順書である。
試験は、最新の安定版Horizon OSとMeta Quest Browserを使用して実施する。

合格には、本書の必須項目をすべて満たす必要がある。デスクトップ上のIWER試験は事前回帰試験として使用できるが、実機試験の代替にはならない。

## 1. 試験範囲

以下を確認する。

- HTTPSサイトからのWebXR起動
- WebXRセッションの開始、終了、再開始
- 頭部追跡と表示の快適性
- 左右Touch Plusコントローラーによる全操作
- 任意機能であるハンドピンチ操作
- デスクトップ表示とXR表示の量子状態の一致
- 3個のBloch球を表示した状態での72 FPS、10分間の安定動作
- 権限拒否、フォーカス喪失、入力機器切断、予期しない終了からの復帰
- XR終了後の2D表示および赤シアンアナグリフ表示
- 物理キーボードを使わない来場者向け操作フロー

## 2. 必要な機材と環境

- Meta Quest 3S
- 左右のMeta Quest Touch Plusコントローラー
- 最新の安定版Meta Quest Browser
- Quest 3Sから到達可能な本番相当HTTPS URL
- 10分以上連続試験できる十分なバッテリー残量
- 安全なプレイエリアと安定したネットワーク
- 赤シアンメガネと通常ディスプレイ
- 必要に応じて、USB接続可能な開発用PC

試験URLには開発用IWERを有効にする `?emulate-xr=1` を付けないこと。

## 4. PC上の事前回帰試験

### 4.1 自動試験

依存関係をインストールし、型検査、単体試験、ビルドを実行する。

```sh
npm install
npm run typecheck
npm run test
npm run build
```

すべて終了コード0で完了すること。

### 4.2 CanvasおよびIWER回帰試験

ターミナルAで開発サーバーを起動する。

```sh
npm run dev
```

ターミナルBで回帰試験を実行する。

```sh
node scripts/verify-canvas.mjs
npm run verify:webxr
```

- デスクトップ2D: 成功

## 5. HTTPS配信確認

1. `npm run build` で生成した `dist/` を本番相当のHTTPSサーバーへ配置する。
2. PCのプライベートウィンドウから配信URLを開く。
3. 証明書エラー、リダイレクトループ、読み込み失敗がないことを確認する。
4. Quest 3SのMeta Quest Browserから同じURLを直接開く。
5. ネイティブアプリのサイドロードなしで2D画面が表示されることを確認する。

合格条件:

- URLが `https://` で始まり、証明書警告がない。
- Canvas、回路、操作ツールバーが表示される。
- `Enter VR` がWebXR対応時だけ表示される。
- 2D画面の基本操作ができる。

## 6. WebXR基本起動試験

1. Quest 3Sを装着し、正面を向いた状態で配信URLを開く。
2. `Enter VR` を1回選択する。
3. 初回のみ表示されるWebXR権限要求を許可する。
4. Bloch球とXR操作パネルが表示されるまで待つ。
5. 頭を左右、上下、前後へゆっくり動かす。
6. `Center` を選択する。
7. `Exit` を選択して2Dブラウザ画面へ戻る。

合格条件:

- 1回の来場者操作でXRを開始できる。
- Bloch球とパネルが初期位置から見つけられる。
- 頭部追跡が一対一で、アプリによるカメラ移動、揺れ、急な回転がない。
- ラベル、ベクトル、球面グリッドが読める。
- `Center` 後、コンテンツが現在の正面の快適な距離へ再配置される。
- `Exit` 後にページを再読み込みせず2D画面へ戻る。

## 8. ハンドトラッキング試験

ハンドトラッキングは任意の入力経路であり、利用できない場合でもTouch Plus操作が機能しなければならない。

1. Questの設定でハンドトラッキングを有効にする。
2. コントローラーを置き、手入力へ切り替わるまで待つ。
3. 左右の手でレイをボタンへ向ける。
4. ピンチで `Next`、`Prev`、`Center`、`Exit` を実行する。
5. コントローラーを持ち直し、Touch Plus操作へ戻れることを確認する。

合格条件:

- 対応環境では左右のピンチ操作が機能する。
- ピンチ1回につきコマンドが1回実行される。
- 手入力が利用できない場合も警告を繰り返さず、コントローラー操作を継続できる。

## 11. 性能および10分連続試験

目標は72 FPSであり、1フレームの予算は約13.9 msである。最も重い構成としてBloch球を3個表示する。

### 11.1 GHZ

1. `GHZ` を選択する。
2. `Qubits` で3個のBloch球を表示する。
3. Auto再生または全ステップの反復操作を開始する。
4. 10分間継続する。

### 11.2 Quantum Teleportation

1. `Quantum Teleportation` を選択する。
2. `Qubits` で3個のBloch球を表示する。
3. Auto再生または全ステップの反復操作を開始する。
4. 10分間継続する。

各試験で記録する。

| プリセット | 平均FPS | 最低FPS | 95%フレーム時間 | 長時間フレーム | Quality変更 | 開始時電池 | 終了時電池 | 判定 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| GHZ | | | | | | | | [ ] PASS / [ ] FAIL |
| Teleportation | | | | | | | | [ ] PASS / [ ] FAIL |

合格条件:

- 72 FPSを安定して維持する。
- フレーム時間は概ね13.9 ms以下である。
- 繰り返す長時間フレームや目視可能な連続スタッターがない。
- 発熱後半に継続的な性能低下がない。
- ブラウザまたはXRセッションが終了しない。
- 適応品質が作動しても、ラベル、Blochベクトル、必須操作が残る。

現在のXRパネルは `Quality: standard` または `Quality: reduced` を表示するが、平均FPSや最低FPSを保存しない。正式な性能証跡には、Quest側の性能計測機能、リモートプロファイラー、または別途追加した軽量フレーム統計を使用する。計測負荷の影響を確認するため、計測ありと計測なしの両方を実施することを推奨する。

Metaの性能資料では72 FPSのフレーム予算を13.9 msとしている。

- [Meta Quest performance frame budgets](https://developers.meta.com/horizon/documentation/unreal/po-perf-opt-mobile/)

## 16. 最終判定

以下をすべて満たした場合のみ、Meta Quest 3S実機対応を合格とする。

- [ ] HTTPSからサイドロードなしで起動した。
- [ ] `Enter VR` が適切に表示され、1回の操作で起動した。
- [ ] XRへ5回連続で入退場できた。
- [ ] 頭部追跡が自然で、不快なアプリカメラ移動がなかった。
- [ ] 左右Touch Plusで全必須操作を実行できた。
- [ ] 全対象プリセットがデスクトップと同じ状態および測定動作を示した。
- [ ] Blochベクトル、混合状態の長さ、ラベル、アニメーションが正しかった。
- [ ] GHZとTeleportationが、それぞれ3球表示で72 FPSを10分間維持した。
- [ ] 切断、フォーカス喪失、権限拒否、予期しない終了から回復した。
- [ ] 物理キーボードなしで来場者フローを完了した。
- [ ] XR試験後も赤シアンアナグリフと全較正機能が動作した。
